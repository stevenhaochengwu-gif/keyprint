# Keyprint

Keyprint is a browser typing trainer that lives in one file, `index.html`, with no build step, no dependencies and no tests. It has four kinds of test. Step up (the default, where each day starts short, every perfect test adds a word and three mistakes take one away), Words, Adaptive (letters unlock one at a time as you learn them) and My text (your own pasted text, text files or PDFs). Tests can also be in Chinese, everyday words typed with a pinyin input method, with the pinyin above each character. It also has an on-screen keyboard with finger colors and hand outlines, daily goals, a Progress page of canvas charts, and an Analysis page that works out where your mistakes come from (keys, confusions, key switches, Shift, fingers, pace, place in the word) and builds a Practice these test from them. Someone new gets a four step welcome over their first test, which Settings can show again. Progress saves in the browser, or in Claude artifact storage when it runs as an artifact. On the site, an account (a username and password, or Sign in with Google) keeps it on every device through a small account service in the site's own Worker, `site-worker.js`. Key based Cloud save, to a Cloudflare Worker that the user runs, still works as before.

## Files

- `index.html` is the entire app, about 11,500 lines of HTML, CSS and JS. Keep it one self-contained file. The owner also runs it as an artifact in the Claude chat app (that is where `window.storage` comes from), so don't split it into modules or add local files, packages or a build step.
- `README.md` is a one-line stub.
- `wrangler.jsonc`, `.assetsignore` and `_headers` deploy the site to Cloudflare (see Deploying). `_headers` is page header config (no framing, `nosniff` and a referrer policy) that Wrangler reads and never publishes.
- `site-worker.js` is the site Worker's script and the account service behind `/api`. It's an ES module exporting `default { fetch }` and two Durable Object classes on SQLite, `Directory` and `Vault`. It has no imports, no packages and no `nodejs_compat`, uses only Web APIs and the Durable Object SQL API, and reaches both classes through plain `fetch` handlers and `stub.fetch` rather than RPC, so Node can import a copy for tests. Unlike `save-worker.js`, it deploys automatically with every push to `main`, and `.assetsignore`'s `*.js` keeps it off the site. Its header points here for the routes and every answer they give, so keep the account service notes below in step with it.
- `save-worker.js` is the Cloudflare Worker behind key based Cloud save (an ES module, `export default { fetch }`). It stores everything in a Workers KV namespace bound as `DATA` and only answers requests with `Authorization: Bearer <SAVE_KEY>`. The owner deploys it by hand in the Cloudflare dashboard, so editing this file changes nothing live. Say so whenever a change needs a redeploy, and keep the app working with the Worker that is already deployed. Accounts don't use it, and key based Cloud save must keep working with it unchanged.

## Deploying

The site is a Cloudflare Worker that serves `index.html` as a static asset and runs `site-worker.js` (`main`) for the account service. `wrangler.jsonc` names that Worker (`typing`, which must match the dashboard exactly), keeps its workers.dev address and declares the `type.stevenwu.org` custom domain. Once the owner connects the Worker to this repo under Settings, Build, every push to the production branch (`main`) runs `npx wrangler deploy`, which publishes the page and the script together.

- **`run_worker_first` is `["/api/*"]`.** Never make it `true`. Every page load would then run the script, count against the Free plan's 100,000 Worker requests a day and get a 429 instead of the page once they run out. Page loads match `index.html`, so they stay free static files. Paths with no file still run the script, which answers them with the usual 404 through `ASSETS`, so crawlers and scanners asking for missing paths count as Worker requests. If that noise ever matters, a WAF rule or rate limit on the zone is the lever. The array form needs Wrangler 4.20 or later, and the build's `npx wrangler deploy` isn't pinned, so it gets the latest.
- **Durable Objects.** The bindings `DIRECTORY` and `VAULT` point at the classes `Directory` and `Vault`, which the migration tagged `accounts-1` (`new_sqlite_classes`) creates on the first deploy from `main`. Never rename the Worker, a class, a binding or the tag, and never remove the migration entry, or deploys fail or the site points at empty storage. A new class needs a new migration entry with a new tag. A new table needs none, since the classes create their own with `CREATE TABLE IF NOT EXISTS`, but the Directory does that in its constructor and a Vault only in `session-new`, so an existing account gets a new Vault table only at its next sign in, and code has to cope until then. A new column in an existing table needs an `ALTER TABLE`, because objects that already exist keep their tables.
- **Preview builds** can't apply a Durable Object migration, so builds of other branches fail until the first deploy from `main`. Keep builds for non production branches off.
- **Vars.** `GOOGLE_CLIENT_ID` and `GOOGLE_ORIGINS` live in `vars` in `wrangler.jsonc`. The client ID isn't a secret, and leaving it empty (as it is now) turns Sign in with Google off. `GOOGLE_ORIGINS` lists the origins registered with that Google client, comma separated, and only those pages show the Google button. Every deploy overwrites vars set in the dashboard, so change them in the file.
- **Secrets.** None are required. The optional `PEPPER` secret is set only in the dashboard, and deploys never remove secrets. Once it's set it must never change or go away (see Gotchas).
- There's no `ratelimits` binding (its status on the Free plan isn't documented), no `secrets.required` (it would fail the first build), no `previews` block and no observability logs (logs could capture headers). Keep it that way.

The assets directory is the repo root, so `.assetsignore` must keep everything except `index.html` off the site, above all `.git`, which can hold a GitHub token on the build machine. When you add a file to the repo, check whether it would be published (`git -c core.excludesFile=.assetsignore check-ignore --no-index -v <path>` shows the matching rule) and extend `.assetsignore` if it shouldn't be. `site-worker.js` matches `*.js`. `_headers` shows as not ignored, which is expected, because Wrangler always takes `/_headers` as config and never uploads it. Its headers only reach static responses (`/api` sets its own), and they don't affect the Claude artifact. Never add Cross-Origin-Opener-Policy there, which would break the Google popup. `save-worker.js` is deployed separately by hand and isn't part of this.

## Running and checking changes

Open `index.html` in a browser, or serve the folder with `python3 -m http.server 8000` and visit http://localhost:8000/. Accounts don't work in either. On `file://` the Account group in Settings says `Accounts work at type.stevenwu.org. Here, your progress stays in this browser.`, and under `python3 -m http.server` the config check gets a 404, so it says `Accounts aren't available at this address. They work at type.stevenwu.org.` The rest of the app works as before. The only network requests are Google Fonts, pdf.js 3.11.174 from cdnjs (loaded only when a PDF is added, with SRI once `APP.pdfIntegrity` is filled in), `/api` on the page's own origin (the config check when Settings opens, then sign in calls and an account's saves), Google's script `APP.googleScript` (only while Settings shows a Google button on an origin in `GOOGLE_ORIGINS`) and the user's Cloud save address.

In this cloud environment Chromium and Playwright are preinstalled, `require('playwright')` works, and `chromium.launch()` needs no options. A `file://` URL is fine and gets working localStorage. Google Fonts fail here with `ERR_TUNNEL_CONNECTION_FAILED`, which is expected. Listen for `pageerror`, because one syntax error anywhere stops the whole app. Top-level `const` and `let` names (`state`, `lesson`, `APP`, `Store`) can be read from `page.evaluate`. After load, keystrokes go to the hidden `#sink` input, which already has focus. Each `browser.newPage()` starts with empty storage, so it is someone new, and the welcome opens over the first test and takes every key until it closes. A script that only wants to type sets `window.keyprintNoWelcome = true` with `page.addInitScript` before `goto`, and then the welcome only opens from Settings (or `openWelcome(false)`). To test an old or odd save, seed `keyprint-state-v1` with `page.addInitScript` before `goto`. Keep test scripts and screenshots outside the repo.

To test Cloud save end to end, run the real Worker locally. Copy `save-worker.js` to a temporary `.mjs` file with the test app's origin added to `SITES`, import it in Node 22, and serve it with `http.createServer` by turning each request into a `Request` and calling `worker.fetch(request, { DATA, SAVE_KEY })`. A `Map` behind async `get`, `put`, `delete` and `list({ prefix, cursor })` (returning `{ keys: [{ name }], list_complete, cursor }`) stands in for KV. Serve `index.html` over http from that origin, not `file://`, or CORS blocks everything. Use one browser context per simulated device, and set `timezoneId` on a context to test time zone behavior. The stand-in KV is instantly consistent and has no rate limit, so wrap it when a test needs real KV behavior.

```js
const { chromium } = require('playwright');
(async () => {
  const browser = await chromium.launch();
  const page = await browser.newPage();
  page.on('pageerror', (e) => console.log('pageerror', e.message));
  await page.addInitScript(() => { window.keyprintNoWelcome = true; }); // skip the welcome
  await page.goto('file:///home/user/keyprint/index.html');
  await page.waitForFunction(() => document.querySelector('#text .c'));
  const text = await page.evaluate(() => lesson.text);
  await page.keyboard.type(text.slice(0, 10));
  console.log(await page.evaluate(() => lesson.pos)); // 10
  await page.screenshot({ path: '/tmp/keyprint.png' });
  await browser.close();
})();
```

To test accounts end to end, build a harness in a scratch folder outside the repo (none is checked in) around the real `site-worker.js`, in Node 22.

- Copy `site-worker.js` to a `.mjs` file and import it. It needs no stubs. To try a different limit (a lower `SIGNUPS_PER_DAY`, say), swap the text in the copy.
- Fake the two Durable Object classes on `node:sqlite`, and run Node with `--no-warnings` to hide its ExperimentalWarning. Each instance's `ctx.storage.sql` wraps a `DatabaseSync(":memory:")` whose `exec(query, ...bindings)` takes ArrayBuffer bindings, gives BLOBs back as ArrayBuffer, refuses BEGIN and COMMIT as workerd does, and returns a cursor with `toArray()`, `one()` and iteration. `ctx.storage` also needs `transactionSync(fn)` (BEGIN, then COMMIT, or ROLLBACK on a throw), `deleteAll()` and `setAlarm()`, plus a way to fire `alarm()`. A namespace has `idFromName(name)` and `get(id)`, whose stub's `fetch(input, init)` calls the one instance for that name with a new `Request`. Don't serialize those calls, because real objects interleave at every await that isn't storage, and the burst tests depend on that.
- Serve it with `http.createServer` on `http://localhost:<port>`, a secure context where accounts work, by calling `worker.default.fetch(request, env, { waitUntil() {} })` with `env = { ASSETS, DIRECTORY, VAULT, GOOGLE_CLIENT_ID, GOOGLE_ORIGINS }`. `ASSETS.fetch` answers `/` with `index.html` read from disk and anything else with 404. Set `CF-Connecting-IP` from a test header, so each simulated device has its own address and the per address limits don't pile up. A second server without the bindings shows the not set up path, one whose `GOOGLE_ORIGINS` leaves the page out shows the Google hint, and `http://127.0.0.1:<port>` stands in for workers.dev.
- Fake Google on both sides. In Node, make RS256 key pairs with WebCrypto, wrap `globalThis.fetch` so `https://www.googleapis.com/oauth2/v3/certs` answers with the public keys (with a `max-age`), and sign ID tokens with any claims. In the browser, `context.route(APP.googleScript, ...)` serves a stand-in for Google's script whose `google.accounts.id.initialize` keeps the config, nonce included, and whose `renderButton` draws a plain button that hands the callback `{ credential }`. `page.exposeFunction` lets the page ask Node to sign a token for the current nonce.
- Patch `Date.now` in Node for the server's clock (sessions, limits, daily copies, a new account's smaller budget) and use `page.clock` for the app's timers. Setting `APP.accountDelay` lower through `page.evaluate` makes saves come sooner.
- To test moving key Cloud save progress into an account, run the real save Worker beside it as above, with the account server's origin in `SITES`.

## State, storage and versioning

- **The `state` object.** It holds `version, settings, profiles, daily, clean, goalMetOn, cheered, docs, docId, removed, step, restoredAt, drillBack, devices, welcomed, savedAt`. `drillBack` is `"zh"` while Practice these has switched Chinese off and `""` otherwise (see Practice these in Gotchas). `welcomed` is when the welcome was closed (ms), or 0 for never. `step` is `{day, words, at}`, how long Step up's tests are on that local day and when that last changed (ms, set by `finishLesson` whenever it grows or shrinks, 0 in saves from before it was timed). `finishLesson` sets `at` to now or one past the `at` it replaces, whichever is later, so a change always beats the copy it changed even when another device's clock is ahead. `hydrate` clamps `at` to between 0 and a day past now. Don't hold it closer to now, or a fast clock's `at` is lowered here but not in that clock's own copy, which then undoes the next change made here. `mergeSaves` keeps the later day's, or on the same day the later change (see `mergeSaves`). Each `profiles[layout]` is `{unlocked, keys, history, customPos, resetAt}`, so letter stats, unlocks and history are kept per layout. `daily` and `clean` (ms per local `YYYY-MM-DD`) are shared by all layouts.
- **Saved shapes are fixed.**
  - Letter stats are `{t, n, e, m, x}`.
  - History entries are `{ts, wpm, acc, dur, words, mode, tries, nk, k, tx, mx, tm}`, with `k[ch] = [avgMs, timed, typed, missed]`. Older entries have no `k` or `nk` and must keep working. A Chinese test has `lang: "zh"` and no `nk`, `k`, `tx`, `mx` or `tm`. Entries without `lang` are English.
  - `tx`, `mx` and `tm` are every keystroke of the test, for the Analysis tab, made by `keyDetail` and `joinDetail` in `finishLesson`. `tx` is the test text. `mx` is `[[i, typed, ms], ...]`, the first wrong key at each position `i` of `tx` that went wrong, with the ms since the key before (left out when there is none, at a test's first key or right after Backspace). Wrong keys typed after it while the mistake still shows (the trail, and every blocked key with Backspace to delete) are not noted again, so `mx` lines up with `errAt`. `tm` is two base 36 digits per character of `tx` (so `tm.length === 2 * tx.length`), the time before the key that typed it right on the first try in 10 ms steps, capped at `APP.idleGap`, or `zz` when there is none (first key, after Backspace, or a missed position).
  - Attempts that end early (a failed try in One mistake restarts, Esc, Tab, a settings change) have no entry of their own. `keepPartial` holds their keys in `unfinished` (not saved, at most `APP.unfinishedChars` characters, dropped on a layout change or Reset progress), and the next finished test on the same layout puts them first in its `tx`, each part ending in a `\n` with `zz` in `tm`. Lesson text never contains `\n`, and the analysis never counts a switch across one. So `tx` can be longer than the text the entry's `wpm` and `acc` describe.
  - Only the newest `APP.detailTests` tests per layout, holding at most `APP.detailChars` characters of `tx`, keep these three fields. `trimDetail` strips the rest, and both `finishLesson` and `hydrate` run it, so merges can't grow it back. Old entries without them, or with ones that don't add up, are skipped by `detailedTests` and work everywhere else as before.
  - Docs are `{id, title, words, passages, at, added, finished}`. Doc text is never stored in the main blob, which is why My text tests keep no `tx`, `mx` or `tm` (`finishLesson` and `holdPartial` skip them). Otherwise a removed text's words would live on in the main save and in the cloud's daily copies, which the save Worker never deletes (an account keeps the last 14).
- **`Store`.** It uses Claude's `window.storage` if present, then localStorage, then nothing. It writes three kinds of key (plus a `keyprint-probe` it sets and removes to test localStorage).
  - `keyprint-state-v1`, the whole state.
  - `keyprint-doc:<id>`, one per text.
  - `keyprint-cloud`, this browser's cloud config (the shapes are below), always with this browser's `device` id (8 to 24 lowercase letters and digits).

  Never rename these keys, or every existing save is orphaned. `wipeLocal` removes the first two kinds straight from localStorage, which is the only place accounts exist.
- **The `keyprint-cloud` shapes.** `loadCloudConfig` reads them and `saveCloudConfig` writes them. `cloudSeen` holds the raw text this tab last read or wrote.
  - `{url, key, device}` is the older key config, still read as key mode, and `{kind: "key", url, key, device}` is what key mode writes now.
  - `{kind: "account", url: "", key, device, user, due, held, heldAt}` is an account. `url` stays empty so an `index.html` cached from before accounts sees Cloud save as off and never sends the token anywhere. `key` is the session token, or empty once the session has ended, when this browser's progress still belongs to `user` (`{id, name, username, email, google, password}`, cleaned by `cleanUser`). `due` lists texts not yet in the account and `held` texts it had no room for (at most 300 ids each, checked by `textIds`), and `heldAt` is when one was last held.
  - `{device, out, why, fresh}` is the signed out marker, and Cloud stays off while it's there. `why` is `out`, `deleted`, `revoked` or `cleared`, and `fresh` stays true until the first load after the sign out has wiped whatever a stale tab wrote.
  - An account config is taken only where `accountPlace()` is `"ok"`, and its token only when `isToken` finds it well formed and naming `user.id`. The token never goes into the DOM, a URL, a backup file or the state blob.
- **Saving.**
  - `scheduleSave` debounces (400 ms by default, 500 from `setSetting`), then calls `saveLocal`.
  - `saveLocal` stamps `savedAt`, writes, marks the cloud copy dirty and calls `scheduleCloud`, which pushes at most every `APP.cloudDelay` (20 s), or every `APP.accountDelay` (2 minutes) for an account. Before any of that it returns at once while `ready` is false, and calls `leaveTab` instead of writing when another tab has signed in or out since this one last looked (see Tabs, signing in and signing out).
  - `flushSaves` runs on `pagehide` and when the page is hidden. It saves locally, then `sendLeaving` sends a slim copy with `keepalive` to this browser's own slot, `keyprint-pending-<device>`, once per batch of changes. The copy carries `leftAt` (this browser's clock) and only this browser's own `left` mark, since its other marks may cover copies whose tests it isn't carrying. The copy holds only tests since this browser's last cloud save (at most `APP.pendingTests` per layout) and the last 3 days of totals, since merging only ever adds. Only the newest of those tests keep `tx`, `mx` and `tm`, up to `APP.leftDetail` characters of them, and the rest reach the cloud with the next regular save. It never writes the main cloud copy, because a hidden page may never run again (phones often stop one right away) and a closing page can't wait to read first. Nothing is sent while `Account.switching`.
  - `pushCloud` runs one `sendCloud` at a time and queues at most one more for everyone who asks meanwhile. Keep it that way, or two saves read the same copy and both write it.
  - `sendCloud` first waits until 1.1 s after its last successful PUT (timed with `performance.now()`, as KV takes one write a second per name). Then `readCloud` reads the main copy and the slot of every browser listed in `state.devices` and in the main copy (an account reads them all in one request instead), `foldLeft` merges each slot whose `leftAt` is newer than that browser's `left` mark and raises the mark, and the main copy is written. Slots are never deleted. The marks make sure each left copy is merged once. It gives up quietly if Cloud save was disconnected, changed or signed out mid-save. `sameCloud` compares `url`, `key` and `kind`, and runs again right after the PUT along with `ready` and the tab check, so nothing is put back once a sign out or disconnect has landed. Never write the main copy without that read and merge, or a stale tab replaces newer progress from another device.
  - `sendCloud` returns at once for an account while `Account.switching` (the account gets nothing until the move into it has merged), and leaves the tab if another tab signed in or out. On success it sets `Cloud.retry` back to 60 s, and for an account starts `uploadDue` and `retryHeld`. A failure goes through `cloudFailed`. Key mode tries again in a minute, as always. An account waits `Cloud.retry`, which doubles after each failure up to `APP.accountRetry` (10 minutes), so a site that's out of requests for the day isn't kept busy.
  - Every `Cloud.call` except a keepalive one gives up if no answer starts within `APP.cloudTimeout` plus 1 s per 10,000 characters uploaded. Once the answer starts, the body can take as long as it needs. This keeps one stuck request from holding up the queue without cutting off big uploads on slow links.
  - `state.devices` is `[{id, seen, left}]`, unioned by `mergeDevices` (max of each) and capped by `hydrate` at `APP.cloudDevices`, most recently seen first. Every save marks this browser as seen. Other browsers only read slots of listed browsers, so `init` saves right away when the cloud copy doesn't list this browser yet.
  - Tabs of one browser share its slot, so each tab folds in the other tabs' local saves through the `storage` event. Keep that listener, or a stale tab's local save or left copy drops another tab's tests.
  - Known limit. KV's delay between locations can drop a browser from the main copy's list (last write wins), and then its newest left copy waits until that browser opens again.
  - `ready` stays false until `init` has hydrated, so nothing can write DEFAULTS over a real save. Keep it that way. A tab that signs out or leaves sets it false again for good, which stops every save from that page.
- **`hydrate` is the one gate for every load.** That covers init, cloud connect, an account sign in (`adoptAccount`, and `clearLocalInPlace` with a deep copy of DEFAULTS), the merge inside `pushCloud`, backup restore and daily cloud copy restore. It rebuilds state field by field and resets any setting whose `typeof` differs from DEFAULTS. It checks enums against include lists or lookup tables and clamps numbers. It caps history at `APP.historyLimit` (and its keystroke detail through `trimDetail`), `daily` and `clean` at 400 days and `removed` at 200. It clamps `welcomed` to a whole number of 0 or more, and a save with any test in any profile but no `welcomed` counts as welcomed (stamped with its `savedAt`), so saves from before the welcome need no version bump and never see it. It never updates `state.version`.
- **Migrations.** To change the schema, bump `APP.version` (currently 8) and add an `if (from < N)` block in `hydrate`. Version 8 moves saves that were on Words to Step up.
  - `from` is `Number(saved.version) || 1`. An object without `version` therefore runs every migration and has its unit, capitals, punctuation, word pool, theme and finger colors forced.
  - Always pass `hydrate` a parsed or `snapshot()` copy that still has `version`. Never pass live state, because `hydrate` clears each state field before reading the same field from its argument, which would wipe profiles, daily, clean and docs. It also keeps the argument's `keys` objects by reference (`cleanKeys` mutates and returns them).
- **New top-level fields.** A new state field goes in the initial `state` and in `hydrate`. If you miss `hydrate`, the saved value is silently dropped on every reload. `mergeSaves` starts from a copy of the newer save, so it only needs code if both copies' values should be combined.
- **Cloud save** (`Cloud`, `pushCloud`, the Cloud save subsection).
  - In key mode it sends bearer-key fetches to the user's Worker. Object names are the state and doc Store keys URL-encoded, plus one `keyprint-pending-<device>` slot per browser (`APP.cloudPending` is the prefix), `backups` and `backup-YYYY-MM-DD`. `keyprint-cloud` never leaves the browser. An account sends the same names to `/api/u/<name>` on the page's own origin, with the session token as the bearer, plus `keyprint-sync`.
  - Status 401 becomes `key`, 500 becomes `setup` and any other failure `reach`. A GET that returns 404 is null. For an account only, a 401 whose body is `Revoked` becomes `revoked`, and 413 and 507 become `full`. Key mode never reads a 401 body. `cloudProblem` passes `key`, `setup`, `revoked` and `full` through and turns everything else into `reach`.
  - One cloud per browser. `renderCloudStatus` hides `#cloudGroup` while an account is in use, says Cloud save is for people who run their own save Worker when it's off and accounts are available, hides the Daily copies row whenever Cloud is off (a session that ended included), and sets `#cloudDaysHint` by kind. `onCloudConnect` sets `kind` to `"key"` and drops a signed out marker, and `onCloudOff` empties `kind` and `cloudSeen`. Daily copy dates show as their UTC day.
- **The Worker side** (`save-worker.js`).
  - `SITES` lists the only origins allowed by CORS (`https://type.stevenwu.org` and the `typing.stevenhaochengwu.workers.dev` address). From any other origin, including a Claude artifact, a `file://` page or localhost, the browser blocks every response and the app reports `reach`.
  - Routes are `OPTIONS` (no key needed), `GET backups` (the daily copy days, newest first), then GET, PUT and DELETE on a name matching `/^[A-Za-z0-9._:-]{1,120}$/`. Doc names decode to `keyprint-doc:<id>`, which fits.
  - A PUT of `keyprint-state-v1` also writes `backup-<day>` if that day has no copy yet. The day is the UTC date, so outside UTC the "day" starts at a local time other than midnight (evening in the US). Daily copies are never deleted.
  - DELETE refuses the main state and daily copies (403). Bodies over 20,000,000 characters get 413. Missing `DATA` or `SAVE_KEY` gives 500, which the app shows as the setup message.
  - Workers KV is eventually consistent. A write can take 60 seconds or more to show up at other Cloudflare locations, same-key writes are limited to one per second (faster ones throw a 429 inside `put`), and the last write wins. Two devices are not guaranteed to see each other's latest save, which is why `mergeSaves` exists and why it must never drop data from either side.
  - A save merges the main copy only if its `savedAt` is newer than `Cloud.seen`. `init` merges the main copy and the left copies at start.
  - `keepalive` only applies to bodies under 60,000 characters, which is why the left copy is slim. Merging only ever adds tests, so leaving older ones out of it loses nothing.
- **The account service** (`site-worker.js`). Its constants sit at the top of the file, unit first in each comment.
  - Routing. Paths outside `/api/` go to `ASSETS`. Every `/api` answer carries `Cache-Control: no-store`, `X-Content-Type-Options: nosniff` and `Cross-Origin-Resource-Policy: same-origin`, and never an `Access-Control-*` header. OPTIONS gets 405, and a request other than GET whose `Origin` isn't the page's own gets 403 (`origin` on auth routes, `Not allowed` on data routes), so no other site can read or send anything. Without the `DIRECTORY` or `VAULT` binding, config still answers with `ready: false`, other auth routes give 500 `setup` and data routes 500 `Setup is not finished`. Anything else under `/api/` gives 404 `route`. Any throw is logged as `console.error("api", <route word>, err.name)` and answered 503 (`later`, or `Try again later`), never 500.
  - Formats. A username is `normalize("NFKC").trim().toLowerCase()` and must match `/^[a-z0-9][a-z0-9._-]{2,31}$/`, and a name in `RESERVED` answers as taken. A proof is 43 characters of base64url (32 bytes), and a uid 20 of `[a-z0-9]`. The token is `kp1.<uid>.<secret>`, returned once in a JSON body and sent only as `Authorization: Bearer`. The user JSON is `{id, name, username, email, google, password}`, where `name` is the username, else the email, else `Google account`.
  - Auth routes are JSON under `/api/auth/`. POSTs need `Content-Type: application/json` (otherwise 415 `type`), at most `BODY_MAX` (8,192) characters (413 `body`) and an object (400 `body`), and a wrong method gets 405 `method`. More than 60 auth POSTs a minute from one address get 429 `busy` with `retry` 60, counted in memory per Worker isolate. Errors are `{"error": "<word>"}`, and `busy` adds `retry` in whole seconds.
  - GET `config` gives `{v: 1, ready, google, googleAt}`, with `google` the client ID when this origin is in `GOOGLE_ORIGINS` and `googleAt` the first listed origin when it isn't, and makes no Durable Object call. `signup {username, proof}` gives 201 `{token, user, created: true}`, or 400 `username` or `proof`, 409 `taken`, 429 `busy`, 429 `closed` (the day's cap) or 429 `full` (the site's ceiling). `signin {username, proof}` gives 200 `{token, user, created: false}`, or 401 `wrong` for an unknown username and a wrong password alike, 429 `busy` or 503 `later`. `google {credential, proof}` gives 200, or 201 with `created: true` when it makes an account, or 400 `credential`, 401 `google` (any failed check, Google not set up here included), 429 `busy`, `closed` or `full`, or 503 `later` when Google's keys can't be fetched.
  - The routes that take the token are `signout {all}` (200 `{ok: true}`, revoking this session or, with `all`, every one), `link {credential, proof}` (200 `{user}`, 409 `linked` when that Google account has its own Keyprint account, 409 `has` when this one already has Google), `password {proof, old, username}` (200 `{user}`, with `old` the current password's proof for a change, 401 `wrong` when it doesn't match, or `username` for a first password, 400 `username` or 409 `taken`) and `delete {confirm: "delete"}` (200 `{ok: true}`, 400 `body` without the confirm). Linking Google, adding a first password and deleting need a session made within `FRESH` (15 minutes) and get 403 `recent` otherwise, and the Directory decides that a password is a first one from its own logins, never from the body. Each of these gives 401 `session` for a malformed, unknown, idle or expired token and 401 `revoked` for a revoked one.
  - Data routes, `/api/u/<name>`, keep the save Worker's names, bodies and statuses, so `Cloud.call` works unchanged. A name must be `keyprint-state-v1`, `keyprint-sync`, `backups`, `keyprint-pending-<device>`, `keyprint-doc:<id>` or `backup-YYYY-MM-DD` (`nameKind`), and anything else, or one that won't decode, gets 400 `Bad name`. GET gives the bytes or 404 `Not found`, and `backups` the day list, newest first. PUT works only on the main copy (up to `MAIN_MAX`, 8,000,000 bytes), left copies (`SLOT_MAX`, 262,144) and texts (`DOC_MAX`, 12,000,000), answering 200 `Saved` or 413 `Too large` (before reading when `Content-Length` says so), and gets 403 `Not allowed` everywhere else. DELETE works only on texts (200 `Deleted`, also when it was already gone) and gets 403 elsewhere. A method other than these gets 405 `Not allowed`.
  - Other data answers are 401 `Signed out` (no token, or an unknown, idle or expired session), 401 `Revoked`, 429 `Slow down` (more than `PUTS_MAX`, 120, writes in 10 minutes, counted in Vault memory, or the bad token limiter), 507 `Full` and 503 `Try again later`. A missing or malformed token is answered without reaching a Vault and isn't counted, since any page can send one from a visitor's browser. Only a Vault's 401 counts, and once one address has 20 of them in 10 minutes its data requests get 429 without reaching a Durable Object. Both in memory limiters hold at most 5,000 addresses and start over past that.
  - `keyprint-sync` is one read in place of 1 + N GETs per save, and never 404. Its body (`application/octet-stream`) is a JSON header `{"v":1,"main":<bytes, or -1 with no main copy>,"slots":[["<device>",<bytes>], ...]}`, one `\n`, then the main copy's bytes and each left copy's in header order, newest written first, at most `SLOTS_MAX` (24). A new left copy past 24 drops the one written longest ago. The Vault copies stored bytes into the frame without decoding them, and `readAccount` splits it.
  - Daily copies. The first main copy PUT of each UTC day is copied to `backup-<day>` inside SQLite, in the same transaction, and only the newest `KEEP_DAYS` (14) stay, where the save Worker keeps every one.
  - Budgets. An account keeps `ACCOUNT_BYTES` (40,000,000) in all, daily copies included, or `YOUNG_BYTES` (4,000,000) for the first `YOUNG` (3 days) after it's made. Texts also have caps of their own, `DOCS_BYTES` (24,000,000) in all and `DOCS_MAX` (200). A text or left copy past any of these gets 507. The main copy is never refused for them. The oldest daily copies go to make room instead, and once that isn't enough, today's is skipped.
  - The site's ceiling. Each Vault tells the Directory its size whenever it has grown or shrunk by `STEP` (1 MiB) since the Directory last heard (`meta.reported`), and the Directory keeps a `sizes` table and their sum. Past `SITE_BYTES` (4,000,000,000) the Directory refuses growth and new accounts (429 `full`). Then texts and left copies get 507, and a main copy is saved without its daily copy, or gets 507 when even that would grow the account by more than `STEP`. A Directory that can't be reached fails texts and left copies with 503 and never holds up a main copy. Deleting an account takes its size out. `SELECT * FROM sizes ORDER BY bytes DESC` in the Directory shows the biggest accounts.
  - Durable Objects. One `Directory` (`idFromName("directory")`) keeps `users`, `logins` (`pw:<username>` with salt, hash and alg, or `g:<sub>`), `limits`, `used` (Google nonces already taken), `sizes` and `meta` (the key for hashing addresses, the day's sign up count, the last prune and the site's bytes). One `Vault` per account (`idFromName(uid)`) keeps `meta` (`uid`, `created`, `reported` and, after a delete, `deleted`), `sessions` (the SHA-256 of each secret, with `created`, `seen` and `revoked`) and `blobs` (each name in parts of `PART`, 1 MiB). The Worker reaches them only through POSTs to `/internal/<route>` that it builds itself (`signup`, `signin`, `google`, `link`, `password`, `remove` and `size` on the Directory, `session-new`, `check`, `fresh`, `end`, `end-others` and `delete` on the Vault) and the Vault's `/data/<name>`.
  - Sessions last `IDLE` (90 days) without use and `LIFE` (400 days) at most, `seen` moves at most once a day, and an account keeps `SESSIONS_MAX` (20) live ones, so a new one pushes out the least recently seen. Sign out, Sign out everywhere and Delete account set `revoked`, and those rows stay until `created + LIFE`, so a browser that comes back much later is told `Revoked` and clears itself. A password change deletes the other live sessions instead, so those browsers see `Signed out`, keep their progress and merge it back when they sign in again. Delete removes the user, logins and blobs at once, and the Vault's alarm removes the rest after `LIFE`.
  - Passwords never leave the browser. It sends `passwordProof`, PBKDF2-SHA256 of the NFKC password with the salt `keyprint:v1:<username>` and `APP.passwordRounds` (600,000) rounds. The Directory stores an HMAC of that proof with 16 random bytes of salt per login (alg `kp1`), or keyed with `PEPPER` when it's set (`kp2`, and a `kp1` row is rehashed at its next sign in), and compares in constant time. An unknown username runs the same HMAC and answers like a wrong password. The rules the server can't check are in `passwordProblem` (at least `APP.passwordMin` characters, and for a new password not the username, not in `EASY_PASSWORDS` and not one character repeated), and the fields stop at 200 characters.
  - Google. `verifyGoogle` checks an RS256 ID token against Google's published keys by `kid`, then `iss`, `aud` and `azp`, `exp` and `iat` with a little skew, `sub`, and a `nonce` that must be the SHA-256 of the proof sent beside it, which only the page that started the attempt holds. The Directory takes each nonce once. Accounts are matched by `sub` only, never by email, which is kept for display when Google says it's verified. A failure logs one reason word, never the token.
  - Limits, exact because the Directory is one strongly consistent object. Sign in and Google attempts count 120 per 10 minutes per address. After 5 wrong passwords for one username from one address, the next try waits 15 s, doubling up to 15 minutes, and each username takes 50 attempts an hour from all addresses. Sign ups take `SIGNUPS_PER_PLACE` (30) in 24 hours per address (then 429 `busy`) and `SIGNUPS_PER_DAY` (500) in a UTC day across the site (then 429 `closed`). An IPv6 address counts by its /64 for attempts and its /48 for sign ups. Addresses are kept only as keyed hashes, for at most a day.
  - Cost. On the Free plan only `/api` and paths with no file count toward the 100,000 Worker requests a day, and an active person makes roughly 44 (each save is `keyprint-sync` and a PUT). Once a limit runs out, `/api` answers 429 or 503, pages still load, practice saves in the browser and the app backs off. `APP.accountDelay` and `KEEP_DAYS` (with its hint) are the first levers.
  - Known limits. Two devices saving in the same instant can still drop one device's newest tests from the main copy, and they come back from that device on its next save. A tab open from before a deploy runs old code with no account listeners. There's no password reset, since a password account has no email, so adding Google is the way back in.
- **Account mode** (the Accounts in the save pipeline subsection and the Accounts subsection).
  - `Cloud.kind` is `""`, `"key"` or `"account"`. `Cloud.user` is the account this browser's progress belongs to, kept after its session ends, and `Cloud.retry` is the account's backoff. For an account `Cloud.url` is `accountBase()` (the page's origin plus `/api/u`) and `Cloud.key` the token. `Cloud.on` is still `url && key`, so an account whose session ended is off but keeps `kind` and `user`.
  - The pipeline is the same, name for name. `readCloud` calls `readAccount`, one GET of `keyprint-sync`, so a save is two requests. Left copies go to the account's own `keyprint-pending-<device>`.
  - `Account` holds the account UI and tab state. `conf` is what `/api/auth/config` offered, `marker` the signed out marker, `due`, `held` and `heldAt` the text lists, `pending` a sign in waiting on the merge question, `busy` an action running, `switching` progress moving between clouds (which pauses this tab's identity checks and its account saves), `leaving` a tab that's reloading and never saves again, `message` an error or step hint shown in place of the note, `note` and `toast` what the first start after a sign out shows, `proof` the secret behind the current Google nonce, `gis` Google's script (0 not loaded, 1 loading, 2 ready, 3 failed), and the `*Armed` timers of the two click buttons.
  - `accountPlace()` says where accounts work. It gives `claude`, `file`, `frame`, `insecure` or `none`, each with a note in the Account group, or `ok`. `loadAccountConfig` asks `/api/auth/config` once per page, with an 8 s limit, when Settings first opens. No answer, a 429 or a 5xx asks again next time, and a 404 or a reply without `v: 1` means this address has no account service.
  - `cloudFailed(err)` notes a failure and says whether to try again. In key mode it only sets `Cloud.error`. For an account, `revoked` runs `clearBrowser("revoked")` on a timer (so `sendCloud` can call it), `key` runs `sessionEnded` and stops, and anything else is noted and retried. `sendCloud`, `sendDoc`, `init` and `onCloudRestore` send every failure through it, and `loadCloudDays` and `uploadDue` only an ended or revoked session.
  - `sessionEnded` keeps the progress here and stops every request. It empties `Cloud.key`, `error`, `seen` and `lastOk`, keeps `kind` and `user`, and saves the config, unless another tab has already signed in again, when it leaves instead. The Account group then offers to sign in again (the same account merges without asking) or Clear this browser.
  - `settleCloud` cancels a waiting save and the retry timer and waits for the running one, ignoring its failure, which is the next owner's to retry. Signing in, signing out and deleting run it before they switch or ask the server.
  - Texts. `cloudDoc` keeps each PUT in `textSends` until it settles. A failed account PUT lists the text in `Account.due`, or on `full` holds it (`holdText`, with the No room toast), and saves the config. `uploadDue` sends due texts one at a time in the background (asking during a run hands back that run). It never undoes a sign in, and it stops at the first failure other than `full`, so the next save that works tries again. Held texts are only in this browser, and `retryHeld` puts them back on the due list once `APP.heldRetry` (a day) has passed since `heldAt`, or at once after a removed text frees room. `settleTexts` waits for `textSends`, joins the other tabs' lists, runs `uploadDue` (twice when a run was already going) and says whether every text is up. `restoreBackup` lists every text as due when its upload fails.
  - Tabs of one browser share the config, and each one only knows the texts it tried. `joinTextLists` folds the stored lists for the same account into this tab's on every account `saveCloudConfig` and on the `storage` event, apart from the ids this tab just settled (`saveCloudConfig(settled)`). A text in both lists counts as held, so a big text isn't sent again with every save.
- **Tabs, signing in and signing out.**
  - `cloudIdentity(raw)` turns a config into whose progress it stands for, `none`, `key`, `account <uid> <token>` or `out <ms>`. `accountChange(a, b)` is true when two differ and either is an account or a sign out, so connecting or disconnecting key Cloud save, or a device id written at start, never reloads other tabs. `readConfigNow()` reads the stored config straight from localStorage.
  - The identity check compares `cloudIdentity(cloudSeen)` with `cloudIdentity(readConfigNow())`. A change means another tab signed in or out, so this tab's progress may belong to someone else, and it calls `leaveTab`. `saveLocal`, account writes in `saveCloudConfig`, `sendCloud` (before reading and again after its PUT), `sessionEnded` and `adoptAccount` (between its steps) all check, and so does the `storage` listener for `keyprint-cloud`. That listener also leaves when another tab removes `keyprint-state-v1` while this one is on an account, and a `pageshow` from the back forward cache checks again.
  - `leaveTab` sets `Account.leaving`, sets `ready` to false, clears the save and cloud timers and dirty flags, and reloads after 300 ms. It never saves first.
  - `adoptAccount(result, keep)` is the one path for every sign in, new account and Google sign in, and nothing changes until the account has been read. With key Cloud save on it first does a last `pushCloud` to the save Worker, then with Add it `fetchCloudDocs` pulls texts that only that cloud has, and with Leave it out `uploadDocs` sends every local text there, so the save Worker keeps everything either way. A failure there stops with nothing switched. Then `settleCloud`, the switch in memory and `readCloud` (a failed read puts `Cloud` back). The config is written next, before anything local changes, so other tabs stop first. Then it clears this browser unless `keep`, empties `here.devices` (left marks from another cloud would make `foldLeft` skip real slots), merges with `mergeSaves(theirs, here, true)` so the account's settings and open text win and every test stays, folds the left copies in and hydrates. When a guest adds their progress, it first takes the account's `resetAt` per layout and `restoredAt` 0, so a Reset progress or restore made here before isn't one of the account's. Texts the account doesn't list become due, and it saves locally, pushes and starts `uploadDue`. If another tab signs in or out meanwhile, `giveUp` puts `Cloud` back, signs the unused session out and leaves, writing nothing.
  - `askAboutProgress` decides whether to ask first. The same account after its session ended merges without asking. An empty browser goes straight in, except that a Google account new to Keyprint always asks (the New account row with Create it and Cancel), so nobody lands in a second, empty account without knowing. Otherwise the merge row asks. A guest gets Add it, Leave it out and Cancel (`#accountKeep`, `#accountDrop` and `#accountCancel`), and progress from another account gets Remove it and sign in and Cancel (`#accountDrop` relabeled, with `#accountCancel` hidden), since it's never merged into someone else's account. Leave it out and Remove it and sign in take two clicks. Cancel signs the new session out, or deletes the account when Google made it just now, so that Google login stays free to add to an account you already have.
  - `clearBrowser(why)` is the only way progress leaves this browser. Sign out, Sign out everywhere, Delete account, Clear this browser and a `Revoked` answer all end in it. It sets `leaving` and `switching`, sets `ready` to false, stops every timer, calls Google's `disableAutoSelect`, writes the signed out marker, then runs `wipeLocal` (`keyprint-state-v1` and every `keyprint-doc:` key, keeping the config and its device id) and reloads. The marker goes first, so every other tab stops before anything is removed. It never waits on the cloud queue, so a cloud save can call it.
  - `finishSignOut` runs in `init` while the marker is `fresh`. It wipes again, because anything there now came from a tab that hadn't stopped yet, sets `fresh` to false and saves the marker (its identity doesn't change, so no tab reloads), and sets the toast and, after `revoked`, the note.
  - Sign out (`onAccountOut`) first saves locally, pushes, settles the texts and checks for held ones. If the account doesn't have everything yet, the button arms as Sign out anyway with a warning, and the warning goes when the button disarms. Then come `settleCloud`, the signout call (best effort for a plain sign out, required for Sign out everywhere) and `clearBrowser("out")`. Delete account runs `settleCloud` first too, so a running save can't come back `Revoked` and clear the browser before the delete answers.
  - `init` reads the config before `Store.load()`, runs `finishSignOut` when the marker is fresh, and clears the browser before drawing anything when the start read answers `Revoked`. A `key` answer keeps the local progress and shows the ended note. It stops before `ready` if the tab is leaving, fills the Cloud save inputs only in key mode, starts `uploadDue` when texts are due, sets `#savedNote` through `renderSavedNote` and shows `Account.toast`.
- **`mergeSaves`.**
  - History is unioned by `ts|wpm`, keeping only entries at or after the later `resetAt`. When both copies have a test, the one with `tx` wins, so a slim left copy never strips a test's keystrokes.
  - When both copies share a `resetAt`, each letter keeps the copy with the larger `n`, and `unlocked` takes the max. Otherwise the copy with the later reset wins both.
  - `daily` and `clean` take the max per day, not the sum.
  - `step` takes the later day's. On the same day it takes the copy with the later `at`, so a step down holds against a copy that grew earlier (taking the larger, as it used to, would undo every step down the next time a cloud copy or another tab merged in). Since `finishLesson` always puts `at` past the step it replaces, a change made after a copy merged in beats that copy however the clocks differ. Two changes made without seeing each other are ordered by their clocks. When either copy has no `at` (0), as in a save from before it was timed, the larger `words` wins, as before.
  - `welcomed` takes the larger of the two, so closing the welcome on one device counts on every device. Backups, restores and the slim left copy carry it like any other field.
  - `keepMine` keeps the local settings, `drillBack` and `docId`.
  - A restore (backup file or daily copy) goes through `restoreFrom(copy)`. It merges the copy into what's here, with the copy's settings and open text taking over, and stamps `state.restoredAt` (and `savedAt`) with now. When two copies have different `restoredAt`, `mergeSaves` first runs `undoResets` on the copy restored less recently, which makes its resets from before the newer restore stop counting. Nothing else is trimmed, so a restore only ever brings things back. That's how it undoes a Reset progress another browser had already synced, without wiping a browser that connects later or work done after the restore. `restoredAt` is capped at a few minutes past now, in case a clock runs fast.
- **Backups** are `{app: "keyprint", version, savedAt, state, texts}`. Restore keeps the texts already here, adds the backup's, and drops a backup text whose words are missing from `texts`. A removed text stays removed, since `removed` is unioned everywhere. With Cloud on, a restore uploads the texts and pushes, and for an account a failed upload lists every text as due. Backups never hold the token.
- **Docs.** Doc ids must match `/^[a-z0-9]{4,40}$/`, or `hydrate` silently drops the document. Changing `APP.mergeWords`, `splitWords` or `pieceWords` moves saved `doc.at` positions onto different passages.

## Conventions

- **Code.**
  - Two-space indent, double quotes, semicolons, trailing commas in multi-line literals, `const` and `let`, template literals and arrow callbacks.
  - Use function declarations for real logic and one-line arrow consts for tiny helpers.
  - Names are UPPER_SNAKE for tables, PascalCase for singletons (`Store`, `Cloud`) and camelCase otherwise.
  - Short local names are normal, such as `s` for settings, `p` profile, `L` lesson, `k` letter stats, `ch` char and `P` palette.
- **DOM.**
  - Build elements with `node(tag, cls, text)` and `replaceChildren`, and hide them with the `hidden` property.
  - Show state through classList toggles that CSS reads.
  - Delegate clicks with `closest("button[data-...]")` and go through `el` for element refs.
  - To restart an animation, remove the class, run `void el.offsetWidth`, then add the class back.
  - Destructive buttons take two clicks, with a changed label and a 4000 ms disarm. Reset progress and Restore this copy add an `armed` class, and a text's Remove button sets `data-armed`. The account buttons (Sign out everywhere, Delete account, Clear this browser, Leave it out, Remove it and sign in) go through `armAccount`, which does both, with `data-armed` set to `again`. Sign out arms as Sign out anyway (`data-armed="anyway"`) only after its save didn't get everything up, and its warning goes when it disarms.
- **CSS.**
  - Colors come from custom properties (the red to green skill ramp in computed `hsl()` is the exception), and themes only redefine variables. Short rules go on one line.
  - Numbers use `tabular-nums`. Figures put `<dt>` before `<dd>` and flip them with `column-reverse`.
  - Classes are short and hyphenated, and state classes are single words. Ids are camelCase, apart from `view-*`, settings inputs `set-*` (except `sdSettings`) and readouts `out-<settingKey>`.
  - Every `<button>` has `type="button"`.
- **Comments.**
  - Write plain full sentences ending in periods, often in the second person, explaining intent above the code. Trailing inline comments are short lowercase fragments.
  - Empty `catch` blocks say why they are empty.
  - Section headers are `/* N. Name ---- */`, padded with dashes to about column 80, and subsections have no number.
  - In APP comments the unit comes first (`// ms between saves`).
- **UI copy.**
  - Use sentence case, second person, short and friendly wording. Contractions are welcome.
  - Full sentences end with a period. Button labels, button states and short toasts don't ("Start over", "Backup downloaded").
  - Feature names are capitalized like proper nouns ("My text", "One mistake restarts", "Text only").
  - Numbers go through `toLocaleString("en-US")` ("1,000"). Negatives use the Unicode minus, gains get an explicit +, and speed units come from `unitLabel()`.
  - Join a label and its value with a comma ("Speed now, 80% of target").
- **Punctuation.** No colons, no double dashes and no em or en dashes in UI copy or comments. The only runs of dashes are the section header rules. Use periods, commas or parentheses instead. The owner dislikes colons and double dashes in prose generally, so follow the same rule in docs and commit messages.
- **Internal ids differ from UI names.**
  - `step` is Step up (`stepWords()` gives today's length from `stepStart` and `stepTop`, and `finishLesson` grows or shrinks it before making the next test), `stepDown` is Down after (the mistakes that take a word away), `custom` is My text, `suddenDeath` is One mistake restarts, `emulate` is Follow key positions, and `weakBoost` is Extra practice for weak letters.
  - Step up is the default mode, but the Practice page never names it (the owner asked for the label to go). In English Step up and Words, `#focus` only shows your weak letters (see Weak letters), and is hidden when there are none or Extra practice for weak letters is off. Chinese Step up shows the same "Chinese, N words" line as Chinese Words. Only the word count under the text, the mistake dots beside it and the tags above the text ("Perfect, now 5 words" and "3 mistakes, now 4 words") show it changing. Settings keeps its button under Text to type and the Step up row with Start, Top and Down after, and the welcome explains it.
- **Stepping down.** After each finished Step up test (English or Chinese), `finishLesson` adds a word for a perfect test, up to Top, keeps the length for fewer than `stepDown` mistakes and takes one word away for `stepDown` or more, never below Start. `stepDown` 0 turns that off, and it is clamped to `APP.stepDownMax` (5), which is as many dots as fit beside a two digit word count at 375px.
  - A mistake here is a place in the text that went wrong, counted once however many wrong keys it took. That's `lesson.missed`, which `typeChar` raises in the same step as `noteMiss`, when `errAt` goes from 0 to 1, so it always equals the number of set `errAt` entries. Each of those places shows red in the text in all three Mistakes options (`.fixed` once typed right, `.bad` in Move on), as the trail before the cursor until it's fixed, or as `.cur.miss` at the cursor once Backspace has taken the trail away (`paintChar` adds it when `errAt` is set, the state is 0 and no trail shows, and `popTrail` repaints the cursor when the trail empties). A space has no letter to turn red, so a missed space at the cursor or a fixed one gets a `--miss-soft` block, and its dot shows in full with Show spaces as dots. The trail's extra wrong keys (and the blocked keys in Backspace to delete) are one place. Backspacing over a place in Move on doesn't take it back, as it still counts toward accuracy, so the dots never go down within a test. A Move on place you've backspaced over shows plain until you type it again, then red.
  - The counter is `#pips` after `#wordCount`, one `<i>` per allowed mistake that gets `.on` (filled in `--miss`) as places go wrong. `renderPips`, called from `updateLive` and `afterMerge`, builds and fills them and sets the `aria-label` and `title` ("2 of 3 mistakes"), with no visible words. It hides them unless the lesson's `mode` is `"step"` (so not in Words, Adaptive, My text or Practice these, whose mode is `"words"`), One mistake restarts is off, `stepDown` is above 0 and Start is below Top (at Top every test is the same length, as `artStep`'s `flat` also knows). At Start (`stepWords()` at or below `stepStart`) they get `.low`, which fades them, and the label adds ", already at the shortest". They have a fixed size and `flex: none`, so filling one moves nothing. The next test starts with all of them empty, since `lesson.missed` starts at 0.
  - A test that took a word away shows `noteStepDown`'s tag in the Perfect tag's place, `showFlourish(text, "down")`, grey (`.flourish.down`) with no ring, light, sound or hold. A test that reaches a goal shows the goal instead, as with a perfect test.
  - `mistakes` values `clear`, `delete` and `move` are Right key clears, Backspace to delete and Move on.
  - Speeds are always stored in wpm, and a letter's speed is `12000 / ms`. cpm is for display only (x5).
  - `language` is `"en"` or `"zh"` (the Language setting, and the EN and 中文 switch under the text), `followInput` is Follow your input method and `pinyin` is Show pinyin.
  - `Cloud.kind` `"key"` is Cloud save with your own save Worker, and `"account"` an account. `Cloud.key` holds the save key or, for an account, the token, and the error `key` means a 401, which for an account is a session that ended.
  - The marker's `why` values `out`, `deleted`, `revoked` and `cleared` are Sign out (or Sign out everywhere), Delete account, signed out from another browser and Clear this browser. A text in `due` is still going up, and one in `held` didn't fit.

## Gotchas and invariants

- **Adding a setting** takes four things.
  - A DEFAULTS entry of the right JS type, because controls are cast by `typeof DEFAULTS[key]`.
  - For enums, a check in `hydrate`'s include lists or lookup tables.
  - Markup with `data-setting`. Seg buttons also need a `data-value` exactly equal to `String(value)`.
  - An `EFFECTS` entry, or changing the setting only saves it. The order of the effect checks in `setSetting` matters.
- **Adding a word pool** needs a `POOLS` entry and an `<option>` in `#set-pool`.
- **Adding a punctuation mark or symbol** needs a `MARKS` entry (ids are single characters, and `group: "symbols"` puts it under Symbols in Settings) and handling in `decorate`. Keep `decorate`'s step order, which is apostrophes, then pairs, then symbol joins, stand-in tokens and prefixes, then wraps, then end marks, with capitals last. Numbers use the id `1`. All of them only apply while the Punctuation and symbols switch is on.
- **Word tiers.** `POOLS` slices `COMMON_WORDS` at 200 and 500, so the `WORD_TIERS` sizes (100, 100, 300, 500) and their order matter. A duplicated word shifts every later boundary. Keep the word list `<script>` before the main one.
- **Load order.**
  - Many functions use names that are declared later, such as `el`, `view`, `ZOOMS`, `POOLS`, `MARK_IDS` and `shiftX`. This only works because they first run inside `init()`, so don't add top-level calls into code that touches later names. Put new startup work in `init()`.
  - Syntax a browser can't parse stops the whole app, not just one feature. `splitPassages` and `titleFrom` already use regex lookbehind, and the code avoids `?.` and `??`.
- **The `el` registry** looks up most ids once, at load, for all sections. A renamed id becomes null and crashes somewhere else later. `#focusCap` must keep its inner span.
- **`[hidden] { display: none !important; }` is load-bearing.** Many elements set their own display and are hidden only through `hidden`.
- **`html, body { overflow-x: clip; }` is load-bearing too.** The board's build up glow (`.board::before`, `inset: -60px -80px`) reaches past the sides of a phone's screen. Without the clip the page scrolls sideways, and mobile browsers widen the layout viewport to fit it, so fixed things like the welcome dialog center on a page wider than the screen and run off its edge. Use `clip`, not `hidden`, which would make `body` a scroll container.
- **Themes.**
  - The dark palette is written twice (the `prefers-color-scheme` block and `:root[data-theme="dark"]`), and the two must stay identical. New variables also go in the light `:root`.
  - The System theme means there is no `data-theme` attribute.
  - The `<html data-theme="dark" data-font="ubuntu">` defaults must match DEFAULTS.
- **Zoom.** Any `data-zoom` value hides the keyboard deck, so Normal must remove the attribute.
  - `applyZoom` sets it only on the Practice view.
  - `setSetting` sets `zoomBack` before calling it.
  - In Text only, Esc leaves. On touch screens (`pointer: coarse`) the `#zenHint` button stays at the top as the way out, since there is no Esc. Elsewhere it is a fading hint that never takes clicks or focus (`tabindex="-1"`, `pointer-events: none`).
  - Entering Text only scrolls the cursor (or the Three lines window) into view, before the zoom animation starts, because the animation's scaling throws off measurements.
- **Text rendering.**
  - `charEls[i]` must line up with `lesson.text`. The caret and the trail span are not in it.
  - `paintChar` overwrites each char's whole className from `lesson.states` (0 waiting, 1 right, 2 right after a mistake, 3 wrong). Any new char class must be added inside `paintChar`.
  - The line-height 1.7 and `calc(1.7em * 3)` height drive `measureLines`. `.w` must stay inline-block with `white-space: pre`, and `.c` inline-block.
- **Layout reads return 0 while a view is hidden.** New layout-dependent code must rerun wherever `measureLines`, `drawHands`, `markNextKey` and `moveCaret` already do, which is showView, applyZoom, resize, `fonts.ready` and the lines and hands effects.
- **Keyboard geometry.**
  - Every row is 15 units (`--U` is `100cqw / 15`), and `BOTTOM_ROW` adds up to 15 on both Mac and PC.
  - `LAYOUTS` rows have 13, 13, 11 and 10 keys, and `FINGER_PATTERNS` and `CODE_ROWS` must match.
  - Fingers 0 to 3 are the left hand, 4 to 7 the right hand and 8 the thumbs.
  - `drawHands` uses fixed SVG ids, so only one hands SVG can exist.
- **`keepPartial`** must run before `lesson` is replaced. `startLesson` and `clearLesson` do this, and `L.counted` stops double counting. Text is generated before it runs, so generation sees the stats from before the partial test. It also hands the partial test's keystrokes to `unfinished`.
- **Keystroke capture.** `typeChar` works out `gap` before it touches `L.start` or `L.last`, notes a miss with `noteMiss` only when `errAt` goes from 0 to 1, and sets `L.gaps[i]` only for a first try that was right. Keep those three rules if you change how mistakes work, or the Analysis tab counts trail keys and Backspace retypes as new mistakes. None of it feeds speed, accuracy, letter stats or goals. `L.missed` goes up next to `noteMiss` and feeds Step up's step down and its dots, so the same rule keeps them from counting trail keys and retypes.
- **Stale settings refs.** A `const s = state.settings` captured before a `hydrate` goes stale.
- **`coolUntil`** is shared by `failAttempt` (whose `hold` is captured after `checkGoals`) and `playCheer` (which adds `APP.cheerHold`). `checkGoals` must stay between tests.
- **Celebrations come in three sizes, and they should stay different.**
  - A perfect test (no mistakes) gets `flourishPerfect`, a small `#flourish` tag above the text and a light along the letter row (`.sequence.shine`, ordered by each key's `--i`). It never holds keys. `perfectRun` counts perfect tests in a row and isn't saved. `checkGoals` returns the goals it celebrated, and a test that reaches a goal shows that instead.
  - The clean typing goal alone gets `flourishClean`, one line traced around the text (`.trace`, built once in the board) with the tag sitting on the line as a label. No overlay, no hold.
  - The daily typing goal, alone or with the clean one, gets `playCheer`, the slow release overlay. `renderCharge` (called from `renderGoal`) builds up to it from `APP.chargeFrom` of the goal by setting `.charging`, `--charge` and `--breath` on the Typing today goal and the board.
  - Sounds are `perfect`, `clean` and `release` in `sound()`, and play only with the Sound setting on.
  - A step down isn't a celebration. Its grey tag (see Stepping down) is news about the next test, so it gets no sound, light, ring or hold, and nothing new for it should ever be bigger than the Perfect tag.
- **Docs in progress.** `finishLesson` and `skipAhead` advance whatever `activeDoc()` is at that moment, because the lesson stores no doc id.
- **The Analysis tab.**
  - `renderAnalysis` runs `analyze` over the current layout's detailed tests only when the tab opens (`showView`) and after a merge (`afterMerge`), never per keystroke. It fills in once there are `ANALYSIS_MIN.tests` detailed tests, and each card has its own minimum in `ANALYSIS_MIN` before a key, switch or group shows. Rankings mix `ANALYSIS_MIN.prior` keys at the overall rate into each rate (`rankRates`), so a rarely typed key ranks a little lower than its raw rate and the bars aren't always in strict order.
  - Key places for reasons and switch kinds come from `keyPlace`, which uses `LAYOUTS`, the finger pattern and `ROW_START` (the key widths before each row, matching `buildKeyboard`). A new layout or finger pattern works without changes as long as those tables stay in step.
  - The cards are plain HTML. `.bars` is one grid and each `.bar-row` is `display: contents`, so the labels, bars and figures line up across rows. Bar lengths are the `--v` custom property (0 to 1).
  - Copy that restates script values. The Rushing notes ("Under half your usual gap" and so on) restate the 0.5, 0.8 and 1.25 cutoffs in `analyze`, and the slow switch cutoff is 1.15 times the usual gap in `renderAnaSlow`.
  - Below 480px wide the brand name is visually hidden so the four tabs fit. A fifth tab needs another look at that.
- **Weak letters** (Extra practice for weak letters, `weakBoost`, on by default).
  - `weakLetters(p, s)` gives up to three letters as `{ch, weakness, why, speed, miss, usual, under}`, with why `"slow"` or `"missed"`, whichever counts more. `speed` and `miss` are the letter's own figures as typed, `usual` the median letter speed and `under` true when it's slow against `targetWpm` rather than the median, all for the tooltips.
  - `recentLetters` walks back from the newest English test with `k` (Chinese tests and old tests without `k` are skipped) until about `APP.weakChars` letters or `APP.weakTests` tests, and works out the window's pace (ms per key) and miss rate. A letter typed fewer than `APP.weakMin` times there (z, q, j) keeps walking back through older tests by itself until it has that many, and one with fewer in all doesn't rank. Each test's average for a letter counts as at most `APP.weakCap` times the pace, and each letter gets `APP.weakPrior` keys at the window's pace and miss rate mixed in, as `rankRates` does on the Analysis tab, so one long pause or one miss can't name a letter typed a few times. Its speed counts once half of `APP.weakMin` were timed. When fewer than six letters rank from the history, the overall letter stats in `p.keys` rank every letter (as the old ranking did). There's no fallback for a single letter, since the overall stats move a lot on one key.
  - `rankWeak` drops letters the word list can't practice. `poolLetters` (built once per pool) holds the letters at least `APP.weakWords` of its words hold, so Common words (200) never names j, q, x or z and Common words (500) never names j or z. The median is still taken over every letter.
  - `weakest` scores slowness against the median letter speed and against `targetWpm`, and mistakes by miss rate, the same formulas the old ranking used. A letter named anew needs a weakness of 0.2. The list it was given last time (`before`) is what keeps the names steady. Those letters stay named down to `APP.weakKeep`, rank with `APP.weakStick` of extra weakness, keep their places at the front of the list and keep their reason unless the other score beats it by 0.15. New letters follow them weakest first, and ties go to the unclamped score and then the letter, so the same history gives the same list. `APP.weakKeep` does most of the steadying. A bigger head start (0.25) left a clearly weaker letter out in up to a tenth of tests, so it stays small. In simulated typists with three letters 1.25 to 1.3 times slower, what `#focus` shows changes after 1 to 2% of Step up tests and 5 to 7% of Words tests (31 and 56% before these rules), and after 60 steady tests one 1.5 s pause on z named it in 1 to 6 of 60 trials and one miss of z, k or v in none (35 to 40 of 40 before). A typist whose letters are all even still sees names come and go after about 15% (Step up) to 37% (Words) of tests, and none at all about a third of the time.
  - `weakCache` keeps the result until the history's length or newest `ts`, `targetWpm`, `wordPool` or the profile object changes, so it ranks once per finished test and never per keystroke. The letter row (`renderSequence`), `#focus` (`renderFocus`) and the next test (`wordsText`) all read the same cached list. The list from before carries across a merge on the same layout (`weakCache.layout`), but not across a reload, so after one the order (weakest first again) or a near tie can come out differently once. Partial attempts change `p.keys` without changing the cache key, so the fallback only moves on with the next finished test, which keeps the named letters and the test text in step.
  - `wordsText` (English Step up and Words only, never Practice these, Adaptive, My text or Chinese) puts a weak letter in `Math.max(1, Math.round(n * APP.weakShare))` of a test's `n` words when `n` is 2 or more. Each goes in its own stretch of the test, so they're spread out, and none goes in the first word, which Capitals starts with a capital (a capital doesn't count toward its letter in `applyKeyStats` or `testDetail`). Each draws a weak letter by its weakness, then a word of the pool that holds it, and every weak letter gets a word when there's room. The rest are drawn uniformly, as with the setting off, still avoiding the same word twice in a row, so they can hold weak letters too. `decorate` runs as before. It can swap a word for a contraction or a number or start a sentence with a capital, so a test with no weak letter left in lowercase is decorated again (up to twelve more times, since four still ran out about once in 8,000 short tests with every mark on).
  - `#focus` shows "Practicing your weakest letters" (or "letter") with `weakChips`, key caps outlined like `.seq-key.drill` in the letter row, grouped by reason ("q z slow", "x often missed") so the status row stays on one line at 1280px even with the last test's change showing. `#focus` gets a `title` saying words with them come up more often and where to turn it off, and each cap, and its outlined letter in the row, gets `weakTitle` ("q averages 86 cpm lately, next to your usual 231 cpm, so words with it come up more often."), since the row's colors come from the overall stats and can show a named letter green. `renderFocus` only does this for English Step up and Words with no drill on, and clears the `title` otherwise. Practice these, Adaptive, My text and Chinese show what they did before. While a drill is on the row outlines the drill's letters instead (see Practice these).
- **Practice these.**
  - `startDrill` builds a plan with `drillPlan` and starts it with `drillLesson(plan)`, which is `startLesson(drillText(plan), attempt, plan)`. The plan sits on `lesson.drill`, and a drill lesson's `mode` is `"words"`, so it never grows Step up, moves My text along (`skipAhead` checks `lesson.drill` too) or unlocks a letter.
  - A drill keeps going until you choose Back to your tests, and every test in it comes from the plan it started with. `finishLesson` starts the next test from the same plan, `restartLesson`, the restart effect in `setSetting` and `failAttempt` pass the plan on, so Esc and One mistake restarts stay in the drill, and Tab in `skipAhead` makes new drill text from the same plan. Pressing Practice these keys again starts a fresh drill from the analysis on screen. Anything that calls `newLesson` (a setting with the `lesson` effect, a layout change, Reset progress, a restore, a cloud merge or sign in that makes a new test) or `clearLesson` ends it. The drill isn't saved, so a reload ends it too.
  - Back to your tests is `#focusBack` on Practice (in `.focus-head`, beside the title, sized so the status row doesn't wrap at 1280px any more than Step up does) and `#anaBack` on the Analysis card, next to the `#anaDrillOn` line. Both call `endDrill`, which starts your usual test with `newLesson` and returns focus to `#sink`. `startLesson` runs `keepPartial` first, and so does `clearLesson` when your usual test is My text with nothing to type, so what you typed of the drill still counts. Both buttons scroll to the top when they come from the Analysis card.
  - Chinese. A drill's keys are English, so `startDrill` switches Chinese off and sets `state.drillBack` to `"zh"` (a fresh drill started during one keeps it). `endDrill` switches Chinese back on. `dropDrillBack` clears it whenever a usual test starts or `clearLesson` runs, so any other way out of the drill (a setting, a restore) stays in English, as before. It's saved, so a copy saved during a drill means Chinese. `hydrate` turns Chinese back on for such a copy unless a drill is still on here, in which case it keeps `drillBack` for Back. `mergeSaves` carries it with the settings (`keepMine` keeps this browser's), so a merge in the middle of a drill never switches Chinese on.
  - `renderDrillOn` shows and hides the two buttons and the on line, and moves the Practice these card above Overview while a drill is on, so a phone shows them without scrolling. The on line names the drill's keys when they differ from the card's (`anaPlan`, from the analysis on screen), since the card's keys move on as you type more tests. `startLesson`, `clearLesson`, `showView` and `renderAnaDrill` run it, so it stays in step with the drill however the drill ends, without running the analysis. `renderFocus` shows the plan's keys while a drill is on, and the letter row outlines the plan's lowercase keys in place of the weak letters. `renderDrillOn` redraws the row whenever the drill differs from `rowDrill`, the one `renderSequence` last drew for, so the outlines switch when a drill starts or ends. Space or Enter on a focused `#focusBack` presses it instead of typing (`onKeyDown`).
- **The welcome.** A native `<dialog id="welcome">` opened with `showModal()`, labeled by its `<h2 id="welcomeName">` ("Welcome to Keyprint" when it opens by itself, "How Keyprint works" from Settings). Its code is the Welcome subsection at the end of section 8.
  - It opens by itself once, from `init()` right after the first test is drawn, when `isNewcomer()` holds (no test in any profile and `state.welcomed` is 0), `window.keyprintNoWelcome` isn't `true` and `Account.marker` is null. A browser that was signed out (or had its account deleted or was cleared) has been used before, and its "Signed out" toast would sit unseen under the dialog's backdrop, so it skips the welcome. The How Keyprint works row at the top of the Test group in Settings opens it again with its Show button.
  - `welcomeSteps()` builds the four steps (typing, Step up, keys and mistakes, goals and progress) each time it opens, with every number and name read from the settings then (`stepStart`, `stepTop`, `stepDown`, `mistakes`, `suddenDeath`, `dailyGoal`, `cleanGoal`, `mode`, `zoom`, `language` and `pinyin`, capitals and punctuation, Show keyboard and Finger colors, `weakBoost`) and from `coarse()`. Step 3 ends with a sentence about your weakest letters showing above the text only when `weakBoost` is on and the test is English Step up or Words. It starts "After a few tests," while `weakLetters` has none yet (a new person sees names after two to four Step up tests), and "Your weakest letters" once it has. It sits there, not on the Step up step, because step 3 was the short one, so the dialog only grows about 4px. A touch screen has no Esc or Tab, so it says to tap the text (and Leave Text only in Text only), with Esc and Tab only for an attached keyboard. Tab gives the next passage only when `passagesOn(s)`, My text in English, since a Chinese test never types My text. The capitals note is left out for My text and Chinese, which `decorate` never touches. The keyboard sentence knows that Zoom other than Normal hides the keyboard just as Show keyboard off does. The last sentence of step 4 comes from `welcomeSaves()`, which offers signing in only where `accountPlace()` exists and says `"ok"`, and a backup file otherwise. So a change to any of those features, or to the goal ring labels, the blue ring, how mistakes count, or Esc and Tab, needs the welcome's copy checked too.
  - Each step's picture is built by `artType` (a Chinese word with its pinyin in Chinese, and a tap in place of Esc and Tab on a touch screen), `artStep` (tests as bars, red where a test had mistakes. With Down after on and One mistake restarts off, the second bar carries the practice screen's dots one short of full and the bar after it is as tall, and the fifth has every dot full and the bar after it is a word shorter. Down after 1 has only the full one. With Down after 0 or One mistake restarts on it's the old picture, a red third bar with no dots and the next one as tall), `artKeys` (the layout's home row in its finger colors) and `artGoals` (real `.goal` markup filled by `fillGoal`), from existing variables only. Keep the steps about the same length, or the short ones look empty. Below 360px the keys and the chart shrink to fit a 320px phone.
  - On a short screen the dialog scrolls inside, with `.welcome-foot` sticky at the bottom, and opening and every step change set its `scrollTop` to 0, so each step starts from its picture with the heading and Next in view.
  - While it's open no key reaches the test. `onKeyDown` returns first thing, `onSinkInput` empties `#sink` and returns, and the composition and `beforeinput` listeners do nothing. The dialog itself takes focus (`tabindex="-1"`), not Next, so someone who starts typing without noticing it presses nothing, spaces included. `onWelcomeKey` (a second document `keydown` listener) treats Enter on the dialog itself as Next, keeps Tab and Shift Tab going round the dialog's buttons (Tab from the dialog itself goes to Next) and pages with the Left and Right arrows. Esc is left to the dialog, which closes on its own, so it never restarts the test. Keep these guards if you add another way for keys to reach the test.

Start typing from Settings goes to Practice first. A backdrop click comes to the dialog itself with coordinates outside its box, and only counts when the press started outside too, so a drag to select its words doesn't close it. When the automatic welcome closes before its last step, a toast says "You'll find this tour in Settings".
  - The dialog sits in the browser's top layer, above the toast and the cheer, whatever their z-index, so a toast shown while it's open goes unseen. Under reduced motion its animations are `none`, since nothing waits on their end events and their delays would still run.
- **Chinese tests.**
  - `ZH_WORDS` is one string of entries split by commas, each a word and then one toneless pinyin syllable per character, with `v` for ü. `ZH_LIST` silently drops an entry whose syllable count doesn't match its characters, so check `ZH_LIST.length` after editing the list.
  - With `language` on `"zh"`, `newLesson` makes `zhText` instead of the mode's text, as long as Step up (`stepWords()`) or Words per test (every other mode). The text has no spaces. `lesson.zh` is `{py, ends}`, the pinyin of each character (`""` for the marks ， and 。) and the index of each word's last character, which drives `wordAt` and `words`. `startLesson` takes it as a fourth argument, and `restartLesson` and the restart effect pass it on. A Chinese lesson's `mode` is `"step"` or `"words"`, so it never moves My text along or unlocks a letter.

- **Reduced motion** uses `0.001ms` rather than `none`, so end events still fire.
- **`.sink`** must stay focusable (opacity 0, not display none) and keep its 16px font size, or iOS zooms on focus.
- **Z-index stack.** The welcome dialog's top layer is above everything. Then toast 30, cheer 20, chart tip 15, zen hint 5, cue 3. The board isolates its own stack (`isolation: isolate`), so its build up glow sits at -1 behind the text and `#flourish` at 1 above the traced line.
- **Passwords and usernames.** `APP.passwordRounds`, the `keyprint:v1:` salt text and the NFKC step in `passwordProof` must never change, or every password stops working. Usernames can't be renamed, because the salt includes them. Once `PEPPER` is set it must stay the same for good, since a changed one makes every `kp2` login answer `wrong` and a missing one makes them answer 503.
- **Never write account progress without the config identity checks.** Local saves, account configs and the account's main copy go through `saveLocal`, `saveCloudConfig` and `sendCloud`, which compare `cloudIdentity(cloudSeen)` with `cloudIdentity(readConfigNow())` first, and `adoptAccount` checks between its steps. Keep any new write behind those checks, or a stale tab writes one person's progress into another's account, or back over a sign out. `Account.switching` turns them off only in the tab that's doing the switch. Backup restore and daily copy restore still call `Store.save` directly, from the tab you're clicking in.
- **Never wipe on a plain `Signed out`.** Only `Revoked` clears a browser. An expired, idle or pushed out session, a password change elsewhere and a lost row all answer `Signed out`, and the progress here may be the only copy, so `sessionEnded` keeps it and stops. Every clear goes through `clearBrowser`, marker first.
- **The Vault never writes for an unknown session.** Its constructor writes nothing, `has()` answers `Signed out` while there are no tables, only `session-new` creates them (and the Worker calls it only after the Directory made or found the user), and every write checks the session again inside its transaction, so a sign out that lands meanwhile wins. A made up token must never create storage.
- **Internal routes stay unreachable from `/api/u`.** The Worker forwards only `https://vault/data/` plus `encodeURIComponent(name)` for a name that passed `nameKind`, with a fresh headers object holding only `X-Kp-Secret` and `X-Kp-Uid`. Never pass the incoming request or its headers on, and never build a Durable Object path from the URL.
- **Same origin only.** Never add an `Access-Control-*` header to `/api`, or other sites can use a visitor's account. Logs carry one route or reason word, never bodies, tokens, proofs, credentials or addresses. A passing problem answers 503, because the app reads 500 as a site that isn't set up.
- **Durable Objects interleave** at every await that isn't storage. Count limits synchronously before the first await, and run each write in `transactionSync` with no await inside. The stateless Worker must never share a pending promise between requests, because a request that waits on another request's promise is cancelled as hung, and its promise then never settles. Share only settled values, as `googleKeys` does. Neither class uses timers, only the storage alarm, so no time is billed while idle. Keep `site-worker.js` free of imports, so Node can load a copy.
- **The token stays out of the page.** It lives only in `keyprint-cloud`, an account config's `url` stays empty, and the Cloud save inputs are filled only in key mode. Any script on the page can read localStorage, which is why pdf.js takes SRI once `APP.pdfIntegrity` is set and Google's script loads only while Settings shows its button.
- **Google's button.** `loadGoogle` loads the script only in Settings, with `Account.conf.google` set and a target showing, and gives up after 15 s with the username and password hint. `startGoogle` runs again after every attempt, for a new proof and nonce, and there's no One Tap and no `use_fedcm_for_button`, because FedCM paths are reported to drop the nonce. `drawGoogle` redraws when the target or theme changes (`applyTheme` calls it), and `.g-btn` keeps `color-scheme: light` so Google's frame doesn't show an opaque box in the dark theme.
- **The Account group shows one thing at a time.** `renderAccount` picks the first that applies, a place where accounts don't work, a step in progress, the merge row, the signed in panel, no config yet, no account service or not set up, then the form. `Account.message` replaces the note while it's set, and each action clears it when it starts and after it succeeds.
- **Tabs reload on any account change.** Signing in, signing out or switching accounts in one tab reloads every other tab of that browser, which interrupts a test there, and they never save on the way out.
